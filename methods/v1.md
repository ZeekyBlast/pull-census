# Pull Census methods, version 1

- **Status:** draft. Becomes binding when the git tag `methods-v1` is set, before `/contribute` accepts its first upload.
- **Code:** the definitions below are frozen in `packages/core/src/tests/`. Every published result cites `methods-v1` and the commit it ran on.
- **Changes:** any change makes a new version (`methods-v2`, …) with its own tag. Old versions stay readable. There are no silent edits.

## 1. What goes in

- **Verified imports only.** Verdicts and Census Tests use pulls fetched through the official history link, with a server receipt. Self-reported files (UIGF) only feed the sensitivity check in section 6.
- **Whole history only.** An import covers everything the game returns, never a chosen slice.
- **Streaks.** Each pool's pulls are split at every 5★. A streak is the pulls from one 5★ (exclusive) to the next (inclusive); its length is the pity of that 5★.
  - The first streak of an import is dropped, because its starting pity is unknown.
  - The last streak is usually still open. Open streaks count as pulls without a 5★ ("censored") and never as a 5★.
  - Character event wishes 1 and 2 (gacha types 301 and 400) share one pity, so they form one pool.
- **Guarantee state** before a 5★ is known only from an earlier 5★ in the same import: after a featured 5★ the next one is a 50/50; after a standard 5★ it is guaranteed. Until the first known 5★, the state is unknown and that 5★ is left out of the 50/50 counts.
- **Unknown 5★.** If a 5★ is neither featured on its banner nor in the standard pool according to the Rules Registry, the featured-rate tests for that pool pause and show "Rules need update". The census never guesses.

## 2. Verdict tests (one per game and pool)

| Test | Question | Data | Test statistic | Sided |
|---|---|---|---|---|
| Base rate | Is the 5★ rate before soft pity the disclosed base rate? | Pulls 1–73 of each streak (1–62 for the weapon pool) | Exact binomial | Two-sided |
| Hidden floor | Are there fewer 5★ in a streak's first 10 pulls than the base rate predicts? | Pulls 1–10 of each streak | Exact binomial, lower tail | One-sided |
| Hard pity | Did any streak run past the disclosed maximum? | Every streak, open and first ones included | Count | Deterministic |
| Featured rate | Is P(featured \| not guaranteed) the disclosed value? | 5★ with a known 50/50 | Exact binomial | Two-sided; one-sided (lower) when a catch-up mechanic such as Capturing Radiance is disclosed |
| 4★ guarantee | Did any 10 pulls in a row pass without a 4★ or better? | Every pull | Count | Deterministic |

- The soft-pity windows (73 and 62) are set before any census data, from the long-known public measurements. Soft pity itself is published only as a measured mechanic.
- With a disclosed catch-up mechanic the true 50/50 is meant to be above the disclosed floor, so only a shortfall counts against the disclosure.
- The deterministic tests flag any single violation, which then goes to the review gate (section 8).

## 3. Census Tests (subgroup comparisons)

Each compares two groups on the base-rate hazard (the window above) and, where the pool has a featured 5★, on the 50/50 win rate. The test is a two-sided two-proportion z-test.

| Census Test | Group A | Group B |
|---|---|---|
| Singles vs 10-pulls | Pulls made one at a time | Pulls inside a 10-pull |
| Account age | Lowest fifth of UID magnitude, within each region | Highest fifth |
| Pull volume | Top fifth of pulls per 30 days | Bottom fifth |
| Returning players | Streaks that start 60 or more days after the account's previous pull | All other streaks |
| Region (one test per region) | America, Europe, Asia, TW/HK/MO | The other three |
| Patch (one per registry patch inside the data) | Streaks that end before the patch | Streaks that start after it; spanning streaks are left out |

## 4. Measured mechanics (no verdict)

Published with the label "measured, not disclosed":

- the soft pity curve: the 5★ hazard at each pull, with 95% Clopper–Pearson intervals
- the 50/50 win rate after k losses in a row (k = 0, 1, 2, 3 or more), where guaranteed 5★ don't reset the count
- the consolidated rate: 5★ per pull over complete streaks, next to the disclosed figure

## 5. Rigour

| Setting | Value |
|---|---|
| Significance | α = 0.001, with Holm correction across every test in a release |
| Intervals | 99.9% percentile intervals from a bootstrap that resamples whole accounts |
| Bootstrap | 10,000 resamples, seed 20261009 mixed with each test's id, so anyone can rerun it and get identical numbers |
| Power | 80% at α = 0.001 |
| Smallest effects sized for | ±25% relative on the base rate; ±5 points on the 50/50 |

- **Minimum n.** Each test has a minimum sample computed from the power settings (normal approximation). Below it the result is "Seeing too poor: n of needed". At the disclosed 0.6% base rate this is 47,446 pulls for the base rate, 38,673 for the hidden floor and 1,543 coin flips for a one-sided 50/50. A Census Test needs 101,755 pulls or 3,405 coin flips in each group.
- **Deterministic tests** need at least one streak (or one run of pulls) to report anything.

## 6. Selection bias

- Imports are whole-history only.
- **Without the latest streak:** every release is rerun without each account's most recent streak in each pool.
- **All tiers:** every release is rerun with self-reported files included.
- Any test whose result changes in either rerun is listed on its page as not agreeing.
- The methods page publishes the census's own sample statistics.

## 7. Verdict wording

Only these strings ever render:

- Verdict tests: "Consistent with the disclosed rate", "Differs from the disclosed rate", "Seeing too poor: n of needed".
- Census Tests: "No difference found", "Differs", "Seeing too poor: n of needed".
- A paused featured-rate test: "Rules need update".

"Differs" always comes with the effect size, the interval, n, and a box on what it does and doesn't mean. Never "rigged", "lying" or "scam".

## 8. Review gate

Any "Differs", and any deterministic flag, goes through two steps before it is published:

1. **Maintainer review:** a check of the pipeline for data bugs, never a vote on the result. Any bug found is noted on the page.
2. **Publisher notice:** the publisher is told and gets 14 days to reply. Their reply is published alongside the result.

Both steps can delay publication; neither can stop it.

## 9. Beta gate

Public release waits for 1,500 complete verified Genshin character-event streaks (about 100,000 pulls from roughly 150 accounts). The first mechanic published is that pool's soft pity curve.

## 10. Calibration

Before tagging, the pipeline is run on the OneBST dataset (about 15.6 million Genshin pulls, 2022). It must find soft pity starting within one pull of 74 and a base rate between 0.5% and 0.7%. OneBST has no licence, so it is used locally for calibration only and is never published.
